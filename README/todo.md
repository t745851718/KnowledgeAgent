## 主要待办

    - 前端显示优化
      1. 后端仍向模型提供重排后的片段，但每个片段使用仅供机器识别的锚点，例如 [[cite:2]]，并要求模型把锚点放在引用该片段的句末或段末。
      2. 模型回答中的锚点不直接展示。前端渲染时会：
           - 删除 [[cite:2]]；
           - 从第 2 条重排片段关联的图片中取图；
           - 紧跟在该句/段之后展示图片；
           - 同一图片只展示一次。
      3. 用户看到的是自然答案与对应位置的图片，例如：
              “RAG 分为索引与检索生成两个阶段。
              [这里展示流程图]”
              而不会看到“来源 2、3”或大段检索原文。
      4. 如果某个锚点没有图片，只删除锚点，不增加任何 UI；如果图片未被模型引用，则默认不展示，避免把无关图片堆在回答底部。
      5. 历史消息保留隐藏锚点与图片关联数据，因此重新打开会话时，图片仍会回到原来的段落位置。
        建议同时收紧系统提示词：禁止输出“来源 1 / 来源 2”等面向用户的编号，只能使用隐藏锚点。这样模型的回答与前端展示职责清晰，图片位置也更符合阅读逻辑

    - 增加网络检索功能
      1. 在现有两条检索路径上再加一条并行分支，网络检索，由前端页面用户可控开启，若未开启，则节点输出空，若开启，则输出topk检索结果，然后和其它检索支路一起混合，采用加权RRF

    - 扩展markdown文件上传
      1. 支持文件夹上传，主要解决用户可以上传一个文件夹，包含md文件及其相对引用图片的asset图片集
      2. 优化原有无图片直接报错的流程，现需将文档图片缺失数/总数返回给前端，用于提示用户缺失图片，可以选择文件夹上传

    - 项目监控平台-admin目录下实现，注意按模块分好目录结构
      1. 监控用户从上传到数据入库各个流程所耗时长
      2. 监控大模型的生成token数以及生成速度，同时要求能对输入给大模型的提示词以及输出内容可视化
      3. 支持项目参数配置，例如检索topk的k,聊天模型名称
