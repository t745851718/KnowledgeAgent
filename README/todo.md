## 主要待办

- [x] 前端显示优化
  1. 后端仍向模型提供重排后的片段，但每个片段使用仅供机器识别的锚点，例如 [[cite:2]]，并要求模型把锚点放在引用该片段的句末或段末。
  2. 模型回答中的锚点不直接展示。前端渲染时会：
       - 删除 [[cite:2]]；
       - 从第 2 条重排片段关联的图片中取图；
       - 紧跟在该句/段之后展示图片；
       - 同一图片只展示一次。
  3. 用户看到的是自然答案与对应位置的图片，例如：
          “RAG 分为索引与检索生成两个阶段。
          [这里展示流程图]”
          而不会看到“来源 2、3”或大段检索原文。
  4. 如果某个锚点没有图片，只删除锚点，不增加任何 UI；如果图片未被模型引用，则默认不展示，避免把无关图片堆在回答底部。
  5. 历史消息保留隐藏锚点与图片关联数据，因此重新打开会话时，图片仍会回到原来的段落位置。
    建议同时收紧系统提示词：禁止输出“来源 1 / 来源 2”等面向用户的编号，只能使用隐藏锚点。这样模型的回答与前端展示职责清晰，图片位置也更符合阅读逻辑

- [x] 增加网络检索功能（首版独立检索分支，已由下方 Responses API 方案替代）
  1. 首版将网络结果作为第三路候选参与加权 RRF；迁移后联网搜索改在回答模型的生成阶段完成，不再进入向量召回或 rerank。

- [x] 扩展markdown文件上传
  1. 支持文件夹上传，主要解决用户可以上传一个文件夹，包含md文件及其相对引用图片的asset图片集
  2. 优化原有无图片直接报错的流程，现需将文档图片缺失数/总数返回给前端，用于提示用户缺失图片，可以选择文件夹上传

- [x] 项目监控平台-admin目录下实现，注意按模块分好目录结构
  1. 监控用户从上传到数据入库各个流程所耗时长
  2. 监控大模型的生成token数以及生成速度，同时要求能对输入给大模型的提示词以及输出内容可视化
  3. 支持项目参数配置，例如检索topk的k,聊天模型名称

- [x] 网络搜索迁移到 ChatOpenAI Responses API 内置联网能力
  1. 使用 `ChatOpenAI(use_responses_api=True)` 调用 Responses API，并在开启联网时绑定内置 `{"type": "web_search"}` 工具；参数名不是 `use_response`。
  2. 保留前端逐次请求的 `web_search_enabled` 开关；关闭时不得向模型传入联网工具，也不得产生联网调用费用。
  3. 将 Responses API 返回的 URL annotations / sources 转换为现有 `Citation`，支持 SSE 返回、消息持久化和历史会话恢复，且只接受安全的 HTTP(S) 来源地址。
  4. 明确处理当前模型与兼容网关对 `/responses`、流式事件和内置 `web_search` 工具的支持差异；不支持时返回可诊断错误，不静默退回无联网回答。
  5. 增加离线 Provider、非流式、SSE、幂等与开关回归；真实测试需显式启用并验证确实产生联网来源，测试后清理会话数据。
