## 主要待办和风险

  - 入库任务使用进程内 asyncio.Task，进程重启后无法恢复。
  - 请求幂等锁和文档写入锁只在单进程内有效，多 worker 会失效。
  - 列表接口先读取大量记录再用 Python 分页，不适合大数据量。
  - Managed Volume SDK 无法删除单个远端文件。
  - 没有正式登录和权限系统。
  - 没有部署配置、容器编排或 CI。
  - LangGraph 只是依赖和规划，尚未真正进入执行链路。
  - 文档与实现存在上述同步问题。
  - 大部分核心代码尚未正式提交到远端。
  - 为全流程跑通编一套可靠测试代码(test/test_flows)，不必每次启动服务验证
  - zilliz volume 替换为 MinIO, 已在.env做相应配置, 请求中生成的文档不存储在本地，统一存储MinIO
  - 双模型嵌入应该是文本和图片一起给到多模态，而不是取MinerU的解析描述文本给到多模态，对于图片的sparse_vector用他的图片描述取给到文本模型是对的
  - workflow转为更高效简洁的langgraph实现
